# 턴제 탑다운 로그라이크 — 마법 시스템 기획서 v0.3

## 프로젝트 개요

- 엔진: Unity
- 장르: 턴제 로그라이크
- 시점: **탑다운 그리드** (고도 없음)
- 그래픽: 고각도 2.5D로 시작, 2D 픽셀 그래픽으로 전환 가능성 유지
- 기본 게임 구조: Shattered Pixel Dungeon 참고
- 마법 시스템: 독자적인 피해·상태·지형 규칙
- 기본 마법: 7개 속성 (불, 얼음, 번개, 독, 대지, 바람, 물)
- 특수 마법: 희귀한 시간 계열
- 핵심 차별점: 마법 간 상호작용과 빌드 조합

### 문서 상태 범례

| 표기 | 의미 |
|---|---|
| **[확정]** | 설계 기준으로 확정된 사항 |

### v0.2 → v0.3 주요 변경점

- 마나 기반 자원 체계 확정
- 시너지를 개별 조합 하드코딩에서 **상태×속성 규칙 기반**으로 전환
- 비전 계열 삭제 (변형은 마법서 시스템이 전담), 기본 속성 8개 → 7개

- 해금형 확장 시스템 "제한해제"(1초당 1틱 실시간 모드) 추가
- 마법 조합 목록 전체를 [임시] 처리

## 1. 기획 목표 [확정]

이 게임은 마법의 단순한 피해량 경쟁보다 마법의 사용 순서와 전장 상황에 따른 전략적 선택을 중요하게 다룬다.

- 턴제 전투를 기반으로 매 행동의 가치가 분명하게 드러나도록 한다.
- 각 마법에 공격, 방어, 상태 제어, 지형 조작 등 고유한 역할을 부여한다.
- 마법서와 아이템을 통해 기존 마법의 성능이나 작동 방식을 변화시킨다.
- 상태 이상과 지형 효과를 연결해 다양한 시너지 조합을 만든다.
- 시간 마법은 일반 마법보다 획득하기 어려운 희귀 계열로 설정한다.
- 마법의 개수를 늘리기보다, 적은 수의 마법으로 다양한 전투 상황과 빌드가 만들어지도록 한다.

## 2. 기술 요구사항 [확정]

그래픽 방식 교체(2.5D ↔ 2D 픽셀), 시간 마법, 실시간 모드를 모두 지원하기 위한 구조 원칙이다. 초기 구현 단계부터 반영한다.

### 2.1 시뮬레이션과 표현의 분리

- 게임 규칙(전투, 상태, 지형, 마나)은 렌더링 방식을 알지 못하는 순수 로직으로 구성한다.
- 시뮬레이션 레이어에 Unity의 Transform, 카메라, 3D 충돌체를 섞지 않는다.
- 로직은 "화염이 (3,4)에 생성됨", "젖음 부여됨" 같은 **이벤트**를 발행하고, 표현 레이어가 이를 3D 이펙트 또는 스프라이트 애니메이션으로 변환한다.
- 마법·상태·지형은 데이터(ScriptableObject 또는 데이터 테이블)로 정의하고, 비주얼 에셋은 ID로만 참조한다.

### 2.2 탑다운 그리드 규칙

- 모든 규칙은 2D 그리드(x, y) 기준으로 계산한다.
- 시야, 사거리, 물 흐름, 전이 경로는 그리드 기반으로 계산하며 3D 레이캐스트나 물리 충돌에 의존하지 않는다.
- 고도는 사용하지 않는 것을 기본으로 한다. 사용하게 되더라도 타일의 선택적 속성 하나로 분리한다.

### 2.3 시간 마법을 위한 구조

- 모든 상태, 지형, 마나, 유닛 정보를 **직렬화 가능한 순수 데이터**로 보관한다. (스냅샷 한 번으로 되감기·기록 가능)
- 턴 처리는 **하나의 틱 파이프라인**으로 통일한다. 상태 지속시간, 지형 지속시간, 마나 회복이 모두 같은 틱 시스템을 따른다.
- 난수는 **시드 기반**으로 한다. 되감기 후 같은 행동이 같은 결과를 내는지의 정책은 추후 정한다. [미정]
- 모든 엔티티에 **고유 ID**를 부여한다. (기록 대상이 사라지거나 위치가 점유된 경우의 처리를 ID 기준으로 수행)
- 되감기용 기록은 최근 N틱을 보관하는 **링버퍼**를 가정한다.

### 2.4 틱 단위 통일

- 모든 지속시간은 **틱** 단위로 정의한다. (턴제에서 1틱 = 1턴, 실시간 모드에서 1틱 = 1초)
- 모든 행동에 **행동 비용(틱)** 필드를 둔다. 초기에는 전부 1틱으로 시작하되, 시간 가속·이동속도 차이를 넣을 수 있게 한다.

## 3. 턴/틱 구조와 "제한해제" 모드

### 3.1 기본 구조: 시계 교체 방식 [확정]

게임 규칙은 "1틱을 진행하라"는 명령만 받는다. 틱을 누가 발생시키느냐만 모드별로 다르다.

| 모드 | 틱 발생 조건 |
|---|---|
| 턴제 (기본) | 플레이어가 행동을 확정하면 1틱 진행. 입력할 때까지 틱 정지 |
| 제한해제 (실시간) | 타이머가 1초마다 1틱 진행 |

- 마법·상태·AI는 모드별로 별도 구현하지 않는다.
- Unity에서는 deltaTime 누적이 아닌 **고정 간격 틱 스케줄러 + 커맨드 큐** 구조를 사용한다.
- 연출은 시뮬레이션과 분리한다. 로직은 즉시 계산하고 애니메이션은 따라오며, 실시간에서는 1초 안에 끝나도록 연출 시간을 스케일하거나 건너뛸 수 있어야 한다.
- 실시간 모드의 입력 규칙(틱 사이 다중 입력 처리, 입력 없을 때 대기 처리)은 구현 시 정의한다.

### 3.2 제한해제의 세부 규칙 [임시]

해금 시스템 중 하나로 제공한다. 아래 항목은 모두 추후 결정한다.

- 영구 해금인지, 런마다 켜고 끄는 토글인지, 전투 중 전환이 가능한지
- 일시정지 허용 여부, 속도 배율(0.5x, 2x 등) 지원 여부
- 두 모드의 보상·기록·업적 분리 여부
- 마나 회복량 등 수치가 두 모드에서 모두 괜찮은지 테스트
- 위험/보상 조합(예: 물+번개)의 난이도 보정

## 4. 마나 시스템 [확정: 마나 사용 / 세부 미정]

마법 자원은 **마나**로 한다.

- 마나로 일부 하드캡(주문당 대상 수 상한 등)을 비용 구조로 대체할 수 있다.
- 마법서의 "마법 자원 소모 감소" 항목은 마나 소모량 감소로 적용한다.

미정 항목:

- 마나 최대치 [미정]
- 마나 회복 방식: 틱당 회복 / 처치 기반 / 아이템 / 조합 [미정]
- 시간 정지 중 마나가 회복되는지 [미정]
- 되감기 시 마나를 복원하는지 (무료 재시도가 되지 않도록 범위 명시 필요) [미정]
- 마법 획득 방식과 장착 규칙 [미정]

## 5. 기본 마법 속성 (7개) [확정]

### 5.1 불 — 공격형
직접 피해와 화상을 부여하고 가연성 지형을 불태운다.

### 5.2 얼음 — 제어형
적을 둔화하거나 빙결시키고, 냉기 지대와 빙벽을 생성한다. 물을 얼려 지형을 바꾸거나 빙결 상태를 다른 공격의 추가 효과로 활용한다.

### 5.3 번개 — 연쇄 공격형
높은 순간 피해와 연쇄 공격을 담당한다. 물이 있는 타일이나 젖은 대상에게 전류를 전달해 여러 적을 공격할 수 있다.

### 5.4 독 — 지속 피해형
중독과 독구름을 통해 지속 피해를 주고 이동 경로를 통제한다.

### 5.5 대지 — 지형·방어형
바위와 벽을 생성하고 적의 이동을 제한한다. 생성된 구조물을 다른 마법으로 변화시키거나 공격 수단으로 활용한다.

### 5.6 바람 — 위치 조작형
적을 밀거나 끌어당기고, 불길과 독구름 같은 구역 효과를 이동시킨다.

### 5.7 물 — 환경·연계형
물을 생성하거나 분사하고, 타일과 적을 젖은 상태로 만든다. 번개의 전도 범위를 넓히고 화염을 약화시키며, 얼음 마법과 결합해 지형을 변화시킨다.

> 변형(관통, 추적, 연쇄 등)은 속성이 아닌 **마법서 시스템**(7장)이 전담한다. 비전 계열은 삭제되었다.

## 6. 시간 마법 — 희귀 특수 계열 [콘텐츠 임시 / 구조 확정]

시간 마법은 일반 마법과 별도로 취급한다. 단순한 피해 속성이 아니라 **행동 순서와 효과 발생 시점**을 변경한다. 획득 난이도를 높게 설정하고, 지속시간·대상 수·자원 소모를 제한한다.

| 마법 | 기능 방향 (임시) |
|---|---|
| 시간 정지 | 플레이어를 제외한 주변 대상의 행동 또는 시간 진행 제한 |
| 시간 가속 | 제한된 조건에서 플레이어에게 추가 행동 부여 |
| 시간 되감기 | 기록된 시점의 일부 상태 복원 |
| 시간 기록 | 대상의 위치, 체력, 상태 등을 기록하고 조건에 따라 복원 |

임시 구성에 대한 검토 사항:

- 시간 정지와 시간 가속은 턴제에서 기능이 겹친다 ("플레이어 추가 턴"). 통합 또는 역할 재정의 필요.
- 시간 가속은 "초당 틱 수 증가"인지 "플레이어 행동 비용 감소"인지에 따라 실시간 모드의 체감이 다르다.
- 같은 마법이 두 모드(턴제/실시간)에서 동일하게 작동하도록 효과를 **틱 단위 규칙**으로 서술한다.
- 되감기/기록의 복원 범위(타일 상태, 마나, 위치 충돌, 보스 저항)를 명시해야 한다.
- 조합으로 인한 추가 행동은 기본적으로 금지한다.

## 7. 마법 강화 및 변형 시스템 (마법서) [확정: 구조 / 세부 수치 임시]

### 7.1 강화형 마법서
- 피해량 증가
- 사거리 증가
- 범위 증가
- 지속시간 증가
- 마나 소모 감소

### 7.2 변형형 마법서
- 투사체 분열
- 관통 및 연쇄
- 적 추적
- 속성 변경
- 처치 시 폭발
- 잔류 마법 지대 생성
- 물 마법을 통한 범위 확장이나 효과 전환

예: 물 마법에 범위 강화를 적용하면 물 웅덩이가 넓어지고, 번개 마법에 연쇄 변형을 적용하면 물로 연결된 적들을 연속 공격할 수 있다.

## 8. 시너지 구조: 상태×속성 규칙 기반 [확정: 방향 / 속성표 대기]

### 8.1 설계 원칙

- 개별 마법 조합("A마법+B마법")을 하드코딩하지 않는다.
- 마법은 **속성과 상태/지형 태그를 부여**하고, 반응은 **상태/지형 × 속성 → 결과** 규칙 표로 정의한다.
- 새 마법이 추가되어도 기존 규칙에 따라 조합이 자동으로 따라오도록 한다.
- 반응 규칙은 데이터 테이블로 관리한다.

### 8.2 규칙 표 [대기]

속성표는 사용자가 제공 예정이며, 제공 후 아래 형식으로 정리한다.

| 대상 상태/지형 | 가하는 속성 | 결과 | 비고 |
|---|---|---|---|
| (예) 젖음 | 번개 | 추가 피해 / 전이 | 예시일 뿐 확정 아님 |
| (예) 중독 | 불 | 독 소모 폭발 | 예시일 뿐 확정 아님 |

### 8.3 조합 안전장치 원칙 [확정]

- 조합 추가 피해에 상한을 둔다.
- 전이 피해는 첫 대상보다 낮게 설정한다.
- 한 번의 주문에서 발동 횟수와 대상 수에 상한을 둔다. (마나 비용으로 일부 대체 가능)
- 동일 상태 중첩은 지속시간 갱신 또는 강도 증가 중 하나만 허용한다.
- 위험/보상 구조를 위해 플레이어도 지형·상태의 영향을 받을 수 있다.

## 9. 상태 이상 및 지형 [임시]

마법 개수를 늘리는 것보다 공통 상태와 지형 규칙을 만드는 것이 장기적 확장에 유리하다. 아래 목록은 모두 임시이며 중복 정리가 필요하다.

### 9.1 상태 효과 (임시)

| 상태 | 주요 기능 |
|---|---|
| 화상 | 일정 틱 동안 지속 피해 |
| 빙결 | 조건에 따라 행동 제한 |
| 둔화 | 이동 또는 행동 효율 저하 |
| 중독 | 일정 틱 동안 지속 피해 |
| 속박 | 이동 제한 |
| 전도 | 번개 효과와 상호작용 |
| 젖음 | 번개·불·얼음과 상호작용 |

### 9.2 지형 효과 (임시)

| 지형 | 주요 기능 |
|---|---|
| 화염 지대 | 지나가는 대상에게 피해 |
| 독구름 | 구역 내 대상에게 중독 부여 |
| 냉기 지대 | 이동 또는 행동 제한 |
| 용암 타일 | 높은 위험을 주는 지형 |
| 빙벽 | 이동 및 투사체 차단 |
| 전도성 광맥 | 번개 효과 전이 |
| 물 타일 | 젖음 부여 및 다른 마법의 매개체 |
| 오염된 물 | 중독을 부여하는 위험 지형 |
| 진흙 지대 | 이동 제한 |
| 빙판 | 이동 특성 변화 및 미끄러짐 |

### 9.3 정리가 필요한 부분

- 제어 효과(빙결/둔화/속박/냉기 지대/진흙/빙판/빙벽)가 서로 겹친다. 막는 대상, 지속 방식, 해제 조건의 차이를 정의해야 한다.
- 중독 vs 화상, 전도 vs 젖음의 역할 구분이 필요하다.
- 한 타일에 여러 상태/지형이 겹칠 때의 **레이어 구조와 우선순위**가 필요하다. (예: 물+독+얼음+불)
- 모든 지형은 지속시간(틱), 중첩 규칙, 파괴 조건, 플레이어/적 적용 효과를 정의해야 한다.

## 10. 물 마법 세부 설계 [임시]

물 마법은 직접 피해보다 **전장의 상태를 변화시켜 다른 마법의 효과를 끌어내는 것**이 핵심이다. 물 마법 자체가 모든 상황에서 강력하기보다, 주변 지형과 다른 마법을 이용할 때 더 높은 가치를 얻도록 설계한다.

| 효과 | 설계 방향 (임시) |
|---|---|
| 물 생성 | 지정한 타일에 물을 생성 |
| 물 분사 | 적을 밀거나 젖은 상태로 만듦 |
| 물 웅덩이 | 여러 타일에 물을 퍼뜨려 지형 효과를 생성 |
| 젖음 | 대상이 일정 틱 동안 물에 젖은 상태가 됨 |
| 물길 | 연결된 물 타일을 따라 일부 효과가 전달됨 |
| 물 제거·흡수 | 기존 물 타일을 제거하거나 자원(마나)으로 전환하는 주문의 확장 가능성 |

젖음의 기본 방향 (임시):

- 젖은 대상은 번개에 추가로 취약해질 수 있다.
- 젖은 대상에게 불을 사용하면 화상 피해가 감소하거나 젖음이 제거될 수 있다.
- 물이 있는 타일에 얼음을 사용하면 얼음 지형으로 바뀔 수 있다.
- 물 타일은 적과 플레이어 모두에게 유리하거나 불리한 효과를 줄 수 있다.

물+번개 제한 원칙:

- 물이 연결된 타일을 따라 전류가 전이된다.
- 전이 피해는 첫 대상보다 낮게 설정한다.
- 한 번의 주문에서 공격 가능한 대상 수에 상한을 둔다.
- 물 타일에 있는 플레이어도 전류의 영향을 받을 수 있게 하여 위험과 보상을 함께 만든다.
- 지배 전략 방지를 위해 물 생성 비용, 적의 물 회피 AI 등 대응 수단을 검토한다.

선택 요소: 빙판으로 이동 경로를 막을지, 다른 마법으로 빙결 상태를 활용할지 판단한다.

## 13. 시간 마법과 일반 마법의 시너지 [임시]

| 조합 | 효과 방향 | 주요 제한 |
|---|---|---|
| 시간 정지 + 독구름 | 정지 중 독구름의 지속시간도 정지 | 시간 정지의 대상과 범위 명시 |
| 시간 가속 + 번개 | 추가 행동으로 연속 공격 | 추가 행동 연쇄 방지 |
| 시간 되감기 + 화염 지대 | 과거 시점의 화염 지대 상태 복원 | 복원 가능한 상태 제한 |
| 시간 기록 + 빙결 | 기록한 대상의 위치나 상태 복원 | 위치 충돌 및 보스 저항 |
| 시간 정지 + 물길 | 정지 중 물의 확산이나 지속 효과를 보류 | 즉시 생성 효과와 지속 효과 구분 |
| 시간 되감기 + 오염된 수역 | 기록 시점의 물 타일 및 오염 상태 복원 | 지형 복원 범위와 처리 순서 정의 |

시간 마법은 희귀한 만큼 강력하게 만들되 기본 마법의 역할을 대체하지 않도록 한다. 피해량 외에도 적의 행동 제한, 추가 행동, 상태 복원으로 얻는 이득을 함께 평가한다.

## 최종 요약

이 게임의 마법 시스템은 **7개 기본 속성**(불, 얼음, 번개, 독, 대지, 바람, 물)과 **희귀한 시간 마법**을 중심으로, **마나**를 자원으로 사용하는 탑다운 그리드 기반 로그라이크이다.

- 불: 피해와 확산
- 얼음: 행동 제어
- 번개: 순간 피해와 연쇄
- 독: 지속 피해와 구역 장악
- 대지: 지형과 방어
- 바람: 위치 조작
- 물: 환경 조작과 속성 간 매개체
- 시간: 행동 순서와 효과 시점 변경

마법서와 아이템은 기본 마법의 수치를 강화하거나 작동 방식을 변화시킨다. 시너지는 개별 조합이 아닌 **상태×속성 규칙**으로 정의하며, 상태와 지형을 통해 마법이 서로 연결된다. 게임 규칙은 시뮬레이션과 표현을 분리한 틱 기반 구조 위에서 동작하므로, 턴제와 해금형 실시간 모드, 2.5D와 2D 픽셀 그래픽 모두를 수용한다.

핵심 방향은 마법의 개수를 늘리는 것이 아니라, 적은 수의 마법으로도 다양한 전투 상황과 빌드가 만들어지도록 하는 것이다.
